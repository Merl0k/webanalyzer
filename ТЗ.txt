Этап 1. Чистим Docker и мусор проекта
Почему это первым

Потому что 11 ГБ — это не нормально. Сначала надо убрать venv из Docker context, иначе каждый rebuild будет тяжёлым и долгим.

Что будем делать

Создадим:

backend/.dockerignore

Исправим:

.gitignore
docker-compose.yml

Удалим из проекта:

.venv
backend/venv
backend/.pytest_cache
backend/searches.db
Результат

Docker image должен стать меньше, сборка должна стать быстрее, а в архив проекта больше не будет попадать мусор.

Этап 2. Исправляем критический баг Celery
Почему это вторым

Потому что сейчас анализ через Docker worker может падать из-за несовпадения аргументов.

Что будем менять

Файл:

backend/app/tasks/pipeline_task.py

Нужно будет изменить сигнатуру задачи.

Файл:

backend/app/routes.py

Проверим вызов:

run_pipeline.delay(query, api_key, g.user_id, depth, max_results, lang)

И приведём задачу под этот вызов.

Результат

Анализ должен нормально запускаться через Celery worker и сохраняться в историю пользователя.

Этап 4. Исправляем ENCRYPTION_KEY и .env
Почему это важно

Если ENCRYPTION_KEY пустой, API-ключи пользователя могут стать нечитаемыми после перезапуска контейнера.

Что будем менять

Файлы:

docker-compose.yml
backend/.env.example
README.md

Добавим нормальную инструкцию:

python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"
Результат

API-ключи будут шифроваться стабильно и не ломаться после перезапуска.
